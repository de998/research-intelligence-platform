# Public release checklist

- [ ] The repository owner has permission to publish the code and architecture.
- [ ] The company has approved any work product developed within the company.
- [ ] The source-site terms and data/database rights have been reviewed.
- [ ] Analyst-created hypotheses and human decisions are approved for release.
- [ ] No database dumps, credentials, local profiles, backups, or verification
      fingerprints are present.
- [ ] No personal information or confidential client/company details are present.
- [ ] The Git history has been reviewed for previously committed secrets/files.
- [ ] A suitable code/data license has been selected by the rights holder.
- [ ] The README accurately states what can and cannot be reproduced.
